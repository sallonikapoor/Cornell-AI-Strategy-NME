01 / THE TOOLS

Three tools, three jobs.

One helps you think, one builds, and one keeps your work safe and puts it online.

The ChatGPT desktop app is your thinking partner.

Use it to brainstorm, plan what to build, ask what a word means, or paste in a screenshot of an error and ask what went wrong. It talks with you about your project. It doesn't change your files.

Codex is your builder.

It works inside one folder on your laptop. It reads what's there, writes and edits files, runs what it builds, and shows you exactly what it changed.

GitHub is where your project lives.

It stores every saved version of your project, so you can always go back. GitHub Desktop is the app that sends your work there, and GitHub Pages turns it into a website anyone can visit.

Which tool for what

Use the ChatGPT app to…Use Codex to…
Brainstorm and narrow down a project ideaCreate and edit your project's files
Ask "what's a commit?" or "explain this error"Run your project and fix what breaks
Plan what version 1 should includeWrite tests and a README
Paste in a screenshot and ask what's wrongMake a change across several files at once

What Codex can do

  • Read your whole project and explain how it works in plain English.
  • Create and edit files from a request like "add a button that clears the form."
  • Run what it builds, notice errors, and fix them.
  • Write tests and run them.
  • Show you every change it made, file by file, before you keep it.
  • Ask your permission before running commands, and stay inside your project folder unless you give it more access.
  • Follow standing instructions you write once in a file called AGENTS.md, like "explain every change in plain English."

Codex comes with your ChatGPT account. Free accounts work on your own laptop, which is everything you need this semester. Paid plans can also send Codex tasks to run in the cloud and open changes on GitHub directly.

Also worth knowing: Claude Code

Claude Code is Anthropic's version of the same idea: an AI agent that reads your project, edits files, runs commands, and asks before it acts. It works in the terminal, in code editors, and in Claude's desktop and web apps, and it reads project instructions from a file called CLAUDE.md. It's included with a Claude Pro plan. We're using Codex because everyone here has access to it, but your project is just a folder of files on GitHub, so you can open it in Claude Code later and keep going.

What these tools won't do for you

  • Decide what's worth building. That's your call.
  • Know whether the result is right. They can sound sure and still be wrong, so you test everything.
  • Take responsibility. If it's in your project, it's yours.
  • Keep secrets safe. Anything you paste in or commit can end up somewhere you didn't intend.

Words you'll hear tonight

Repository (repo):
A project folder that GitHub tracks, along with its full history.
Commit:
A save point. A snapshot of your project with a short note about what changed.
Push:
Sending your commits from your laptop up to GitHub.
Clone:
Making a copy of a GitHub repository on your laptop.
Diff:
The list of exact changes between two versions. Added lines show in green, removed lines in red.
Deploy:
Putting your project on the internet.
GitHub Pages:
GitHub's free hosting. It turns a repository into a website.
README:
The front page of your repository. It explains what the project is and how to use it.
AGENTS.md:
A file of standing instructions that Codex reads before every task.

02 / PICK YOUR PROJECT

Pick something small you'd actually use.

The best first project solves a small problem you have and has room to grow.

The rules

  • It runs in a web browser. No app store, no logins, no server.
  • It uses no real personal information. No real bank data, passwords, or anything from client work. Made-up examples are fine.
  • Version 1 fits in one sentence. You'll add to it every week, so start small.
  • It can grow. Later weeks add data, a connection to another service, and search, so pick something where those could make sense.

Write your sentence

A tool that helps [who] [do what], starting with [one feature].

  • A tool that helps me track my spending, starting with adding expenses and seeing totals by category.
  • A tool that helps me plan my week, starting with listing assignments and how many days until each is due.
  • A tool that helps my club pick events, starting with a list I can filter by day.
  • A tool that helps me cook for friends, starting with scaling a recipe to any number of servings.
  • A tool that helps me train, starting with logging workouts and showing this week's total.

Ideas that can grow

Is it the right size?

Too big for version 1:

  • User accounts or logins
  • Sharing between people
  • Payments
  • An AI chatbot inside it
  • Connecting to your real email, bank, or calendar

About right:

  • One screen
  • One main thing you can do
  • Results you can check by hand
  • Saves to your own browser, if it saves at all

Ask me three quick questions about my classes, hobbies, and small daily annoyances. Then suggest five ideas. For each one, give the one-sentence first version and two features I could add later.

Write your sentence down somewhere you can copy it. You'll paste it into Codex twice tonight.

03 / SET UP

Set it up once, use it all semester.

Four apps and accounts, then your project's home. Start steps 1 to 4 right away, since the downloads take the longest.

You'll need a Mac or Windows laptop.

On a Chromebook or iPad, the apps in steps 2 to 4 won't install. Follow Plan B in section 06 instead, and you'll still ship tonight.

  1. Create your GitHub account.

    Go to github.com/signup. Use a personal email you'll keep after graduation, not your school email. Choose a professional username, because it becomes part of your project's web address, like yourname.github.io. Verify your email when GitHub asks.

    Then go to Settings → Emails and turn on Keep my email addresses private, so your email address doesn't appear on your public work.

    You're done when: you can see your profile at github.com/your-username.

  2. Install GitHub Desktop.

    Download it from desktop.github.com, install it, and choose Sign in to GitHub.com. It finishes signing in through your browser.

    If it asks you to configure Git, keep your name and choose the private GitHub email it offers (it ends in users.noreply.github.com).

    You're done when: GitHub Desktop opens to a screen that says "Let's get started."

  3. Install the ChatGPT desktop app.

    Download it from chatgpt.com/download for Mac or Windows, install it, and sign in with your ChatGPT account. If you don't have one, you can create a free account there.

    You're done when: you can send a message in the app.

  4. Get Codex.

    Codex comes with your ChatGPT account. In the ChatGPT desktop app, look for Codex in the sidebar or app switcher and open it. If your version doesn't show it, download the Codex app from openai.com/codex and sign in with the same ChatGPT account.

    You're done when: Codex asks you to choose a project or a folder.

  5. Claim your student credits.

    Go to chatgpt.com/codex/students and verify that you're a student. Codex already works on a free account. The credits give you a lot more room to build.

    You're done when: the page confirms your credits.

  6. Create your project's repository.

    On github.com, click + in the top-right corner, then New repository.

    • Repository name: short, lowercase, words joined with hyphens, like spending-tracker.
    • Visibility: Public.
    • Check Add a README file.
    • Click Create repository.

    Now click the green Code button, then Open with GitHub Desktop. When GitHub Desktop asks where to save it, make a folder called Codex inside your Documents folder and choose it. Click Clone.

    You're done when: GitHub Desktop shows your repository and says "No local changes."

  7. Open your project in Codex.

    In Codex, start a new project and choose your repository's folder: Documents → Codex → your repository name. Check that it says Work locally under the message box, and leave permissions on Default.

    You're done when: Codex shows your folder name and is waiting for your first message.

  8. Give Codex its standing instructions.

    Copy this prompt, replace the bracketed part with your project sentence, and send it to Codex.

    Create AGENTS.md

    Create a file named AGENTS.md in this project with exactly the content between the lines below. Replace the text in brackets with my project sentence: "[paste your project sentence here]"

---
# Instructions for AI coding agents

## About this project
[project sentence]
It's built by a student who is new to coding, so explain everything in plain English.

## Rules
- Build a static website using only HTML, CSS, and JavaScript. No frameworks, build tools, or installs.
- Keep it simple: index.html, plus style.css and script.js if needed.
- It must work when index.html is opened directly in a browser and when it's published on GitHub Pages.
- Never add logins, servers, databases, paid services, API keys, passwords, or real personal data.
- If the project needs to remember things, save them only in the browser (localStorage).
- After every change, summarize what you changed in two to four plain-English bullet points, and tell me exactly how to test it.
- Keep README.md up to date: what the project does, how to use it, and a list of changes.
- If my request is unclear or too big, ask me one question or suggest a smaller first step instead of guessing.
---

    You're done when: you can see AGENTS.md in your project folder.

  9. Get your first win.

    Send Codex this message:

    Hello page

    Create index.html with a heading that says "Hello from [your first name]" and one sentence describing my project. Then tell me how to open it in my browser.

    Open index.html from your project folder (double-click it) and check that it appears in your browser.

    Then save your first commit. In GitHub Desktop, you'll see your new files listed. In the Summary box at the bottom left, type Add hello page, click Commit to main, then click Push origin at the top.

    You're done when: you refresh your repository on github.com and see index.html and AGENTS.md there.

Commits are your save points.

Commit every time something works. If Codex later breaks something, you can always go back to the last commit (section 06 shows how).

Step 2: Test it

An AI agent will tell you its work is done. Your job is to check. Before you try anything, write down what should happen. That way the result can't talk you into it.

Write at least five tests in three kinds:

Normal.

The everyday use. Does the main feature do what it should?

Edge.

The limits: zero, an empty box, a very large number, reloading the page.

Wrong input.

Something a person might type by mistake, like letters where a number goes.

Step 3: Explain it

Write the README

Rewrite README.md for someone visiting my project on GitHub. Include:
- The project name and one sentence on what it does and who it's for
- How to use it, in three steps
- A "Tests" section with this table: [paste your filled-in test table]
- A "Build log" section with three to five short entries. Each entry says what I asked for, what happened, and how I checked it. Use this conversation to draft them, and keep them honest, including anything that went wrong.
- A "Changes" section listing what's been built so far

Keep it short and plain.

Read the README Codex wrote and fix anything that isn't true. Commit with Write README and push.

How to check Codex's work without reading code

  • Read its summary. Does it match what you asked for? If it mentions something you didn't ask for, ask why.
  • Look at which files changed. GitHub Desktop lists every changed file. If Codex touched files you didn't expect, ask it to explain.
  • Skim the diff. In GitHub Desktop, click a file to see its changes: green lines were added, red lines were removed. A huge change for a small request is a warning sign.
  • Try it yourself. Your test table is the final word, not Codex's summary.
Ship it →
05 / SHIP IT

Put it on the internet.

GitHub Pages turns your repository into a website for free, in about two minutes.

  1. Make sure everything is pushed.

    In GitHub Desktop, if you see Push origin with a number next to it, click it. Then check your repository on github.com: you should see index.html, AGENTS.md, and README.md.

    You're done when: GitHub Desktop says "No local changes" and nothing is waiting to push.

  2. Turn on GitHub Pages.

    On your repository's page on github.com, click Settings, then Pages in the left sidebar. Under Build and deployment, set Source to Deploy from a branch. Set the branch to main and the folder to / (root), then click Save.

    You're done when: the page says your site is being built.

  3. Open your live site.

    Wait a minute or two and refresh the Pages settings. A link appears at the top, like https://your-username.github.io/spending-tracker/. Open it. Then open it on your phone, too.

    You're done when: your project works at that link.

  4. Put the link on your repository.

    On your repository's main page, click the gear icon next to About. Check Use your GitHub Pages website, then click Save changes.

    You're done when: your live link shows on the right side of your repository's page.

  5. Share it.

    Post your live link in the NME Slack channel.

Public means public.

Anyone can see your repository and everything that's ever been committed to it, even after you delete it later. Never commit passwords, API keys, real personal data, or anything from client work.

If your site doesn't show up

I get a 404 page. +

Wait two more minutes and refresh. Then check that index.html is in the top level of your repository (not inside another folder) and is spelled exactly index.html, all lowercase.

The page shows up, but it looks plain or broken. +

File names on the internet are case-sensitive. If your page links to Style.css but the file is named style.css, it works on your laptop but not online. Ask Codex: "My page works locally but loses its styling on GitHub Pages. Check every file name and link for mismatches."

My latest changes aren't showing. +

Did you commit and push? Check GitHub Desktop. If you did, wait a minute, then do a hard refresh (Cmd+Shift+R on a Mac, Ctrl+Shift+R on Windows).

06 / WHEN YOU'RE STUCK

Everyone gets stuck. Here's what to do.

Most problems tonight fall into one of these.

Codex built something different from what I asked for. +

Go back to your last save point. In GitHub Desktop, right-click the changed files and choose Discard changes. Then ask again with a smaller, more specific request. One feature per message works better than three.

I see an error I don't understand. +

Take a screenshot and paste it into the ChatGPT app with: "I'm new to coding. Explain this error in plain English and tell me what to ask Codex to fix it."

Codex is asking permission to run a command. +

Read it first. If it's working inside your project folder and the explanation makes sense, approve it. If you're not sure, paste the command into the ChatGPT app and ask what it does. Don't approve anything that deletes files outside your project or installs software you didn't ask for.

I hit a usage limit. +

Switch to a smaller model in Codex's model picker, which lets your credits go further. If you're fully out, keep planning and writing tests in the ChatGPT app, and come back when your limit resets.

GitHub Desktop won't let me push. +

Click Fetch origin, then Push origin again. This usually happens after you edited something on github.com, like the README.

I broke something and don't know when. +

In GitHub Desktop, open the History tab. Every commit is listed with its summary. Find the last one that worked, and ask Codex: "My project worked at the commit named '[summary]'. Something since then broke [what's wrong]. Find what changed and fix it."

Plan B: no Mac or Windows laptop, or setup failed

You can still ship tonight with just a browser.

  1. Create your GitHub account and your repository (steps 1 and 6 in section 03). Skip the "Open with GitHub Desktop" part.
  2. In ChatGPT (the app or chatgpt.com), paste the Build version 1 prompt from section 04, and add: "Put everything in a single index.html file."
  3. Copy the code it gives you into a plain text file named index.html. Or, on github.com, open your repository, click Add file → Create new file, name it index.html, paste the code, and click Commit changes.
  4. Turn on GitHub Pages the same way (section 05, step 2).

You'll miss out on Codex testing and fixing its own work, so set up Codex on a Mac or Windows laptop before next week.
